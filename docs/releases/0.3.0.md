# mochi-web 0.3.0 — unpublished candidate

**Publication held:** whole-page parity regressions in the qualification projects
remain unresolved. The checks below cover specific contracts, not completed
semantic conversion. These notes must be reviewed again before publication.

Mochi now exports reviewed, editable TanStack Start applications with typed source,
Base UI compositions, Bun, Tailwind v4, and Motion. Capturing a site and reconstructing
its source remain separate steps: a deployed-file mirror is not presented as a
semantic application.

Install:

```sh
cargo install mochi-web --version =0.3.0 --locked
```

The package is `mochi-web`; the command and Rust library are `mochi`.
The source is the commit tagged `mochi-web-v0.3.0`.
[Changes since 0.2.0](https://github.com/enkyuan/mochi/compare/mochi-web-v0.2.0...mochi-web-v0.3.0).

## Editable application source

- `plan-source` prepares evidence for interpretation. `export --authored-spec`
  consumes a reviewed, evidence-bound specification and emits typed components,
  feature modules, shared layouts, separate content, and physical TanStack routes.
- `components/ui` contains only direct Base UI exports. Site navigation, menus,
  dialogs, forms, switches, tabs, and accordions are composed in application code.
- Transparent page entries import directly into routes without redundant generated
  wrapper components or empty content files.
- Source names reject compiler identities and hash suffixes. Built asset hashing
  remains confined to build output.
- Fonts, shared tokens, globals, and scoped CSS Modules have explicit ownership.
  Reviewed design stylesheets can replace empty generated definitions without
  silently creating two conflicting token or font sources.
- Reviewed TypeScript, SVG geometry, GLSL shaders, and optional Three.js modules
  support owned graphics. Local media and fonts have descriptive source filenames,
  SHA-256 checks, declared provenance, and a validated import graph.
- Unused modules/assets, unresolved imports, remote CSS asset URLs, path traversal,
  conflicting definitions, and inputs changing during export are refused. Export
  stages a new directory and never overwrites an edited project.
- Reports and specifications live under `.mochi/`; generated build/cache directories
  are ignored. Authored applications contain no recovered-controller dependency.

The pinned starter uses Bun 1.4.4, React 19.3.1, Base UI 1.9.0, Tailwind 4.3.5,
Motion 14.10.1, TanStack Start 1.169.5, and TanStack Router 1.170.46. Compatibility
recovery also retains its separate React 19.2.7 template for matching captured code.

## Capture and analysis

- `clone --analyze` and `analyze` use deterministic subtree fingerprints to identify
  repeated structure and page-template candidates.
- `clone --source-evidence` records responsive DOM observations, computed styles and
  custom properties, readable stylesheet rules, fonts, controls, resources, and PNGs.
- `check-evidence` validates completeness and integrity offline. `model-project`
  produces traceable route, component, asset, and styling candidates.
- Bounded concurrent asset downloads and a validated response cache reduce repeated
  fetches. Cached bodies require server revalidation; there is no stale fallback.

## Interpretation and qualification

The bounded TypeSafe/Jev adapter supports local planning, replay, response validation,
and explicit live request/token/cost/deadline limits. Jev classifies proposals; it
does not author components or replace controllers. No paid live Jev qualification or
provider billing reconciliation was performed. Ordinary capture and export make no
model calls.

Local qualification covered reviewed source packs for nine routes across Natural,
Infinite Garden, and Microsoft AI. These are qualification inputs, not bundled site
presets. Checks included frozen Bun installs, builds, typechecks, desktop/mobile
route health, selected Base UI interactions, and absence of recovered imports and
opaque source filenames. Natural's menu geometry was compared with the reference
at three desktop widths; Garden's footer was checked against its captured equations
and rib endpoints. These checks do not establish whole-site pixel equivalence.

Rust formatting, Clippy, unit/integration tests, and all five browser suites are
release gates. The authored browser fixture verifies direct Base UI behavior and
ordinary edits to emitted typed content and shared tokens. Publication additionally
requires a clean package dry run, exact-commit CI, a fresh registry install, and the
matching GitHub release build.

## Migration and current scope

`export` now requires either `--authored-spec <file>` or an explicit
`--compatibility` flag. Add `--compatibility` when intentionally requesting structural
replay, `--interpretation` comments, or `--recover-client-route`. Existing projects
are not rewritten. Export a new candidate before migrating edits.

TanStack Start and Tailwind v4 are the implemented authored output adapters. Astro,
SvelteKit, additional routing adapters, and StyleX output are not implemented.
Authored export still requires reviewed semantic decisions and source modules;
`plan-source` is evidence preparation, not automatic arbitrary-site code synthesis.
External services, authentication, forms, and uncaptured routes are not recreated
merely because their links appear in a capture.
